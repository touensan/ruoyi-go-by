# 用户工作台与管理员叠加架构

RuoYi-Go BY 从 `v1.3.0` 起默认采用同一应用、同一登录入口、同一用户工作台的双身份
信息架构，不再把“用户后台”和“管理员后台”实现成两套互不相干的前端。

## 默认规则

1. `/index` 是所有登录用户共享的工作台，页面首先服务于用户自己的账户与业务。
2. `common` 是基础用户角色，只授予用户侧菜单。
3. 超级管理员沿用现有超级权限规则，因此会同时看到用户侧菜单与全部管理菜单。
4. 需要创建非超级管理员时，应给账号同时绑定 `common` 和一个或多个管理角色。
5. 管理角色只承载运营、配置、审核等管理权限，不重复创建用户账户菜单。
6. 自助注册必须绑定启用状态的 `common` 角色；角色缺失或停用时注册安全失败，不能
   创建一个登录后没有菜单或意外拥有管理权限的账号。

## 后续项目如何扩展

- 面向客户的服务、订单、资产、API、授权、资料等入口放在“我的账户”或新的用户侧
  一级目录，并授予 `common`。
- 前端把 `account` 目录渲染为“我的服务”分界线，它不是可展开子菜单；目录下的
  控制台、市场、资产、订单、兑换中心等页面在侧边栏直接显示。
- 用户数据接口必须按当前用户做归属过滤；菜单可见不等于数据隔离。
- 商品、全局配置、用户管理、审计、发布等运营入口放在管理目录，只授予对应管理角色。
- 管理员需要预览用户流程时，直接使用同一工作台和用户菜单，不创建管理员专用副本。
- 自定义管理角色采用权限叠加：`common` 提供用户能力，管理角色提供额外管理能力。

## 菜单与角色基线

| 范围 | 默认菜单 | `common` | 超级管理员 |
| --- | --- | --- | --- |
| 共享工作台 | `/index` | 可见 | 可见 |
| 用户服务 | `控制台、服务市场、兑换中心、积分与订单、个人资料` | 可见 | 可见 |
| 积分运营 | `积分管理、兑换中心` | 不可见 | 可见 |
| 系统管理 | 用户、角色、菜单、配置、日志 | 不可见 | 可见 |

全新安装直接使用仓库根目录的 `ruoyi.sql`。从 `v1.2.0` 升级时，先备份数据库，再
执行 `sql/upgrade/v1.3.0-user-workspace.sql`，再执行
`sql/upgrade/v1.4.0-points-exchange.sql`。升级脚本兼容 MySQL 5.7+，会保留项目
自行添加的非系统菜单映射。

## 积分与兑换不变量

- `balance_minor` 以百分之一积分存储，充值时 1 元对应 1 积分。
- 充值、兑换码、购买和人工调整必须写入不可跳过的积分流水。
- 兑换码明文只在创建时返回一次；数据库只保存 HMAC-SHA256 摘要和掩码。
- 同一兑换码只能成功兑换一次；同一任务对同一平台账号、同一提供商账号只能领取一次。
- 雨云提供商有独立开关，默认关闭；API 密钥查询不回显，关闭后不影响通用兑换中心。
